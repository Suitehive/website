**What you'll learn:** how to read logs for one service or all of them, how to make them more detailed, and how much log data Docker keeps.

## Read logs

```sh
suitehive logs                 # last 200 lines of every service
suitehive logs mail            # one service
suitehive logs auth -f         # follow new lines (Ctrl-C to stop)
suitehive logs calendar --tail 1000
```

The service names are `caddy`, `postgres`, `nats`, `auth`, `mail` and `calendar`. `suitehive logs` wraps `docker compose logs`, so from the install directory you can also use Docker directly:

```sh
cd /opt/suitehive && docker compose logs --since 1h mail
```

## Log format

Auth, Mail and Calendar write structured JSON, one object per line, to standard output. Every line carries the `service` and `version`. Lines written while handling a request also carry `request_id`, `org_id`, `user_id` and, when tracing is on, `trace_id` and `span_id`.

```json
{"time":"2026-10-13T09:12:44Z","level":"WARN","msg":"readiness check failed","service":"mail","version":"edge","check":"nats","err":"..."}
```

The services don't log message bodies, passwords or tokens.

To follow one request across services, search for its `request_id`:

```sh
suitehive logs --tail all | grep '"request_id":"<id>"'
```

## Change the log level

`SH_LOG_LEVEL` in `.env` sets the level for Auth, Mail and Calendar: `debug`, `info` (default), `warn` or `error`.

```sh
cd /opt/suitehive
sed -i 's/^SH_LOG_LEVEL=.*/SH_LOG_LEVEL=debug/' .env
docker compose up -d
```

<Aside type="tip">
Set it back to `info` when you're done. `debug` is verbose and can fill the log quickly on a busy server.
</Aside>

`SH_LOG_FORMAT=text` gives human-readable lines in development, but the installer's `docker-compose.yml` doesn't pass it through to the containers.

## Retention

Every container uses Docker's `json-file` log driver with rotation: at most 3 files of 10 MB each per container. Older lines are discarded. To keep logs longer, ship them elsewhere (for example with a log collector reading Docker's logs) or save them yourself:

```sh
suitehive logs --tail all > suitehive-logs-$(date +%F).txt
```
